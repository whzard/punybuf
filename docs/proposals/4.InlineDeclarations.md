# Reworking inline declarations
Make inline declarations easily searchable and no longer tied to their parent type

## Use
Currently, inline declarations are seldom useful since they only work to group data within one type and one type only. They cannot be referred to from other contexts, however they can be used more than once inside a certain type. This creates weird error messages.

This is fine:
```pbd
Owner = {
	inlined_field: InlineDecl {
		field: String
	}
	bad_reference: InlineDecl
}
```
But this gives a weird error:
```pbd
Owner = {
	inlined_field: InlineDecl {
		field: String
	}
	another_inline_field: BadInlineDecl {
		bad_reference: InlineDecl
	}
}
```

```
error: type `InlineDecl` is inline and cannot be referenced outside `Owner`
|
| Owner = {
| ----- inside `Owner`...
|
|  inlined_field: InlineDecl {
|                 ---------- ...`InlineDecl` is declared inline...
|
|  another_inline_field: BadInlineDecl {
|                        ------------- ...but inside `BadInlineDecl`...
|
|   bad_reference: InlineDecl
|                  ~~~~~~~~~~ ...`InlineDecl` is referenced, outside of `Owner`
|
| Owner = {
| ----- info: even though inside `Owner`...
|
|  another_inline_field: BadInlineDecl {
|                        ------------- ...`BadInlineDecl` is declared inline...
|
|   bad_reference: InlineDecl
|                  ~~~~~~~~~~ ...you may reference `InlineDecl` only directly from inside `Owner`, not from `BadInlineDecl`
```

This means we also must invent names to group certain fields together, only to be never used anywhere ever again.

This is inflexible. To fix this, we might want to allow inline declarations to be referenced from anywhere instead. Then we're faced with the problem of searching our .pbd files.

## Proposed syntax
```pbd
SomeStruct = {
	field: InlineDeclared = {
		thing: String
	}
}
```
The syntax is `<field-name>: <type-name> = <type-decl>`.

The `InlineDeclared` can be referenced from anywhere.

The old inline declaration syntax is proposed to be deprecated and warned on use.
