# Grouping
Let fields be grouped together.

## Use
Allow grouping fields together without making and having to name another struct.

Groups allow for logical grouping of fields.

## Proposed syntax
```pbd
SomeStruct = {
	ungrouped: String
	duplicate: String
	field_group: {
		duplicate: UInt
		another_field: String
	}
}
```
The `{...}` after a `<symbol>` `:` within a struct declaration marks a group. Grouped fields only share a namespace within that group.

Double nesting groups is not allowed.
> [!todo] Should it be?

Before this, inline declarations would be used as a form of grouping, however, they needed a name within the global namespace.

Groups don't impact other fields within that struct or the layout of the struct on the wire. Adding a field inside a group is a breaking change, just like adding a field in the struct.

Adding existing fields to a group is not a breaking change, provided they retain their order.

## Proposed IR changes
The group field name is not included, instead the groups are flattened by including a `"group"` property on a field definition with the string value being the group name field.

A major version bump is required as the names inside the group may conflict with the other field names, which codegens may not expect.

Grouped fields are laid out one after the other on the wire and thus do not require any changes in the binary format.

## Proposed Codegen changes
Codegens should generate an anonymous struct or object for group fields when that's possible, or prefix the grouped field names with the name of the group.
