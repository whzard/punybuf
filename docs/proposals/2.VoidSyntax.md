# Spcecial Void Syntax
This proposal would simplify the void syntax by just allowing (or requiring) to not put anything in the return value of the command.

## Use
Currently, commands returning `Void` are special in that they cannot have error enums (because they don't need any acknowledgement). However, this isn't represented in any way in the syntax, and instead is signalled by an error:
```pbd
command: {} -> Void ![Hi]
#                   ~~~~~ commands that return `Void` cannot respond with errors
```

The `Void` type can syntactically be put into structs, which is also invalid, since it doesn't have a representation on the wire:
```pbd
MyStruct = {
	my_field: Void
#             ~~~~ the reserved type `Void` is only allowed in command returns
}
```

## Proposed syntax
Make it at least allowed for a command to not have anything in the return type position, and automatically assigning it to be `Void`.
```pbd
command: {
	some_field: String
}
```
Would be equivalent to:
```pbd
command: {
	some_field: String
} -> Void
```
This would make it clear that the command is a "fire-and-forget" instead of a command that may return something

Maybe deprecate the old `-> Void` syntax in favor of having nothing in its place. Then remove the type `Void` and only special case the return for compatibility reasons, unless there is another `Void` defined.

## Proposed IR changes
Remove the `Void` type. Instead replace it with a `void` boolean key on a command object in the JSON.
This will require a major version bump.
